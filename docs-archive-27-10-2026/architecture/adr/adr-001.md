# ADR-001: Mô hình OA trên FE — tách "record OA (Comvia)" khỏi "kết nối Zalo thật"

**Trạng thái:** Accepted (Product Owner duyệt)
**Ngày:** 2026-10-02

## Bối cảnh
Ref: `docs/issues/ISSUE-003-dashboard-oa-section-create-oa-popup.md`, `docs/handoff/backend-requests.md` BR-03/BR-04.

Hiện FE chỉ có **một** mô hình OA: OA = một kết nối Zalo qua OAuth. `app/app/w/[workspaceId]/oa/page.tsx` đọc `GET /oa/status` và chỉ cho hai hành động Kết nối (`POST /oa/connect` → redirect `authorizationUrl`) / Ngắt (`POST /oa/disconnect`). Không tồn tại khái niệm "record OA nội bộ" tách khỏi kết nối, không có CRUD, không có upload avatar/logo.

PO (2026-10-02) chốt mô hình mới: mỗi workspace có **đúng 1 OA** (1-1 cứng). Tách thành 2 hành động độc lập:
1. **Tạo OA** = tạo record OA nội bộ trên Comvia (nhập tay: `name`, `code`, `avatar`, `logoLight` 400x96, `logoDark` 400x96), lưu DB, KHÔNG cần OAuth.
2. **Kết nối** = chạy OAuth Zalo hiện tại, gắn kết quả (oaId Zalo, token, trạng thái) vào record đó.

Ràng buộc PO đã chốt: (a) field nhập tay là nguồn dữ liệu độc lập — kết nối OAuth KHÔNG ghi đè, không đồng bộ 2 chiều; (b) `code` chỉ là nhãn nội bộ, không đối soát `oaId` Zalo; (c) 1-1 cứng — có record thì ẩn hẳn nút "Tạo OA".

Backend (BR-03/04) chưa hiện thực model/endpoint. SA thiết kế FE trước; chốt tên field/path cuối cùng chờ backend.

## Các phương án đã cân nhắc

### Phương án A: Giữ một mô hình phẳng, nhồi field nhập tay vào `GET /oa/status` hiện có
- Ưu: ít thay đổi; tái dùng trang OA hiện tại gần như nguyên vẹn.
- Nhược: trộn hai vòng đời khác nhau (record do user quản lý vs trạng thái OAuth do hệ thống quản lý) vào một type. Vi phạm ràng buộc PO "độc lập, không ghi đè" — rất dễ để code vô tình đồng bộ field. Không biểu diễn được trạng thái "có record nhưng chưa kết nối". Mâu thuẫn với BR-03 (backend tách 2 nhóm endpoint).
- Tham chiếu: hiện trạng `oa/page.tsx` + `GET /oa/status` §6.3.

### Phương án B: Hai type / hai nhóm endpoint tách bạch ở FE, FE tự suy ra trạng thái UI từ tổ hợp 2 trục
- FE mô hình hóa 2 nguồn dữ liệu tách rời: `OaRecord` (record nội bộ) và `OaConnection` (trạng thái Zalo thật, giữ `GET /oa/status` hiện có). Trạng thái UI suy ra từ tổ hợp (có record?) × (đã kết nối?).
- Ưu: khớp ràng buộc PO "độc lập"; khớp BR-03 (2 nhóm endpoint); biểu diễn được đủ các tổ hợp; tái cấu trúc `oa/page.tsx` rõ ràng; tiền đề gửi ZNS vẫn bám đúng trục kết nối.
- Nhược: nhiều type + nhiều lời gọi API hơn; FE phải hợp nhất 2 nguồn khi render.
- Tham chiếu: BR-03/04; mô hình PO chốt; pattern tách "resource" khỏi "connection/integration state" phổ biến khi một bản ghi nội bộ liên kết tới tài nguyên OAuth bên thứ ba.

## Quyết định
Chọn **Phương án B**.

FE mô hình hóa hai trục độc lập:
- **Record OA (Comvia)** — có/chưa có; field nhập tay do user quản lý.
- **Kết nối Zalo thật** — chưa kết nối / đã kết nối (`CONNECTED`) / lỗi-cần-kết-nối-lại (`TOKEN_EXPIRED`/`RECONNECT_REQUIRED`/`CONNECTION_ERROR`).

Rút về **3 trạng thái UI thực tế** (box thông tin OA, `components/oa/oa-info-box.tsx`):
1. **Chưa có record** → nút "Tạo OA" (mở popup form, chạy CRUD, KHÔNG OAuth).
2. **Có record, chưa kết nối (hoặc lỗi kết nối)** → hiện info nhập tay + nút "Sửa" (sửa record) + nút "Kết nối"/"Kết nối lại" (chạy OAuth hiện tại). Ẩn hẳn "Tạo OA".
3. **Có record, đã kết nối** → hiện info + trạng thái "Đang kết nối" + nút "Sửa" (vẫn sửa được field nhập tay, độc lập) + "Ngắt kết nối".

Tiền đề gửi ZNS/template giữ nguyên: chỉ khi `connection.status === CONNECTED`.

**Interface spec theo hợp đồng backend BR-03/04** (`docs/handoff/backend-responses.md`; code xong, chờ deploy — nối API thật sau khi backend báo deploy live):

Nhóm 1 — CRUD record OA + upload ảnh (3 endpoint riêng):
```
GET   /workspaces/:workspaceId/oa                 -> OaRecord            (Owner + Member)
POST  /workspaces/:workspaceId/oa                 (JSON: OaRecordInput) -> OaRecord (Owner)
PATCH /workspaces/:workspaceId/oa                 (JSON: Partial<OaRecordInput>) -> OaRecord (Owner)
POST  /workspaces/:workspaceId/oa/avatar          (multipart field `file`) -> OaRecord (Owner)
POST  /workspaces/:workspaceId/oa/logo-light      (multipart field `file`) -> OaRecord (Owner)
POST  /workspaces/:workspaceId/oa/logo-dark       (multipart field `file`) -> OaRecord (Owner)
```
```ts
// Khớp hợp đồng BR-03/04 (shape thống nhất cho CRUD + upload).
type OaRecord = {
  id: string;
  workspaceId: string;
  name: string;
  code: string;                  // nhãn nội bộ, không đối soát Zalo
  description: string | null;
  avatarUrl: string | null;      // URL /public/oa/<wsId>/<file> — FE ghép base URL
  logoLightUrl: string | null;   // 400x96
  logoDarkUrl: string | null;    // 400x96
  createdByUserId: string | null;
  createdAt: string;
  updatedAt: string;
  connection: OaConnection;      // NHÚNG trong record — không cần gọi /oa/status riêng
};
// Chỉ các field text qua JSON; avatar/logo gửi qua 3 endpoint multipart riêng.
type OaRecordInput = {
  name: string;
  code: string;
  description?: string;
};
// connection nhúng trong GET /oa (không trả token).
type OaConnection = {
  status: string;              // OaConnectionStatus (NOT_CONNECTED | CONNECTED | ...)
  connectedAt: string | null;
  oaId: string | null;
};
```
Ràng buộc hợp đồng (ảnh hưởng orchestration FE):
- **Thứ tự bắt buộc:** POST record OA **trước**, rồi mới upload ảnh / connect. Upload hoặc connect khi chưa có record → `400`.
- **1-1 cứng:** tạo OA lần 2 → `400 "Workspace already has an OA"`.
- **Ảnh:** chỉ PNG/JPEG, ≤ 2MB; `logo-light`/`logo-dark` đúng 400×96 (sai → 400); `avatar` không ép kích thước.

Nhóm 2 — Kết nối Zalo (GIỮ NGUYÊN §6):
```
POST /workspaces/:workspaceId/oa/connect    -> { authorizationUrl }
POST /workspaces/:workspaceId/oa/disconnect
GET  /workspaces/:workspaceId/oa/status     (giữ cho luồng connect; dashboard dùng connection nhúng trong GET /oa)
```
Backend đã gộp `connection` vào `GET /oa` → FE đọc trạng thái kết nối từ record, không cần lời gọi `/oa/status` song song cho box dashboard. Việc gộp này KHÔNG đổi 3 trạng thái UI ở trên (đã dự phòng từ đầu).

## Hệ quả
- `app/app/w/[workspaceId]/oa/page.tsx` được tái cấu trúc: không còn chỉ một mô hình kết nối; phản ánh record + connection. Logic nút chuyển theo 3 trạng thái trên.
- Dashboard (ISSUE-003) thêm `components/oa/oa-info-box.tsx` dùng cùng logic trạng thái với trang OA.
- Thêm `components/oa/image-upload-field.tsx` — tái dùng `comviaMultipartFetch`, không thêm tầng upload mới. Theo hợp đồng thật, bổ sung validate client **≤2MB + PNG/JPEG** (ngoài 400×96 cho logo) và hỗ trợ **preview từ URL cũ** (mode edit: backend trả `*Url`, không phải File — chỉ upload lại ảnh user chọn mới).
- **Orchestration khi nối API thật (TICKET-019):** vì upload tách 3 endpoint và phải sau POST record, `oa-record-modal` submit theo chuỗi: POST record → (nếu có) upload avatar → logo-light → logo-dark, tuần tự; xử lý lỗi từng bước, rollback/thông báo khi record đã tạo nhưng upload ảnh lỗi (chi tiết chẻ ở TICKET-019).
- **Box "Thông tin OA":** `GET /oa` chỉ trả `createdByUserId` (không có tên) → **ẩn dòng "Người tạo"** cho tới khi backend bổ sung tên; bật lại khi có. (Hiện box đã không render dòng này — giữ nguyên, không thêm.)
- **`components/ui/modal.tsx` thêm prop `size`** (vd `md` mặc định = `max-w-2xl` hiện tại, `lg`/`xl` rộng hơn cho layout 2 cột của popup Tạo OA) — thay đổi component UI dùng chung, SA chấp nhận; mặc định giữ nguyên hành vi cũ để không ảnh hưởng nơi đang dùng.
- Tiền đề gửi ZNS bám trục kết nối (`CONNECTED`), không đổi so với hiện tại.
- **Thời điểm:** backend code xong nhưng chưa deploy — Dev chỉ nối API thật sau khi backend báo deploy live (TICKET-019 Blocked).
- **Điều kiện xem lại quyết định:** nếu PO sau này bỏ ràng buộc 1-1, xem lại logic ẩn nút "Tạo OA". Các điểm còn lại đã khớp hợp đồng thật, không còn là dự kiến.
